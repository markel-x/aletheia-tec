# Incremento 1 · Inspección, supuestos y selección del perfil

Fecha: 2026-09-30

## Qué funciona

- Alcance, supuestos y objetivos no funcionales documentados (`docs/00`).
- Perfil único `ALT-P1` seleccionado con versiones, madurez, formato exacto, algoritmos, resolución/rotación de claves, vinculación, estado, privacidad y brechas frente a HAIP (`docs/01`).
- Arquitectura de monolito modular, secuencias de emisión, presentación/verificación y revocación, matriz de permisos y mapeo a AWS (`docs/02`).
- Modelo de datos con clasificación y retención (`docs/03`); 10 ADRs.
- **Núcleo `aletheia.vc` implementado y probado** (≈1 400 líneas; sin dependencias de web ni de BD):
  - Emisión SD-JWT VC con divulgación selectiva (incluida recursiva), señuelos en todos los niveles y orden de digests.
  - Reconstrucción de claims conforme a RFC 9901 §7.1 (duplicados, conflictos, disclosures no referenciadas, elementos de array).
  - Presentación con selección de disclosures y KB-JWT (`sd_hash`, `aud`, `nonce`, `iat`).
  - Firmantes: `LocalDevSigner` (bloqueado fuera de `development`/`test`) y `KmsSigner` (`DIGEST` + DER→R||S + autocomprobación).
  - Token Status List: codificación de 1/2/4/8 bits, compresión zlib, límites anti-bomba, token `statuslist+jwt`.
  - Verificador con 11 comprobaciones separadas y resultado `valid` / `invalid` / `indeterminate`.

### Revisión independiente
Un agente revisor, sin participación en la escritura, auditó el núcleo contra RFC 9901 y draft-21 y encontró 6 problemas y 3 menores. **Todos fueron corregidos y tienen prueba**:
1. JSON profundamente anidado provocaba `RecursionError` no controlado (medio).
2. KB-JWT aceptado sin solicitud contra la cual validar `aud`/`nonce` (medio) → ahora `indeterminate`.
3. Replay dependía del llamador → consumo atómico inyectado, sólo tras validar la prueba.
4. `iat` exigido aunque SD-JWT VC lo define opcional (interoperabilidad).
5. `cnf.jwk` / `status.status_list` podían ocultarse un nivel más abajo.
6. `_sd` anidados sin ordenar ni señuelos (privacidad).
Menores: datos tras el flujo zlib, lista de estado con `iat` futuro, `_sd_alg` anidado.

## Qué **no** demuestra esta evidencia

- **Interoperabilidad externa del formato SD-JWT completo:** sólo se contrastó con vectores de especificación y con PyJWT a nivel JWS. Falta la prueba con `@sd-jwt/sd-jwt-vc` (npm bloqueado aquí) y con un wallet real.
- **Integración real con AWS KMS:** el cliente KMS es simulado.
- Ninguno de los criterios de aceptación se cumple aún *de extremo a extremo*: no hay API, base de datos ni flujo OID4VCI.

## Limitaciones del entorno (bloqueantes para continuar aquí)

PyPI, npm, GitHub y los registros de HashiCorp responden 403 por política de red; FastAPI, SQLAlchemy, Alembic, psycopg y boto3 no están instalados; Docker Hub no es accesible (las imágenes se validaron con una base sustituta, ver ADR-0011). Ver `docs/00-alcance-y-supuestos.md` §5.
